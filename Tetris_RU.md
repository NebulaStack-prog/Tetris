## Часть 1. Основной документ.

### 1. Заголовок и базовая информация.

• **Название:** Tetris

• **Назначение:** Проект № 7. Продукт.

• **Фаза проекта:** Phase I.

• **Технологический стек:** Python (библиотека Pygame).

• **Статус проекта:** Полностью завершен.

### 2. Краткое описание проекта.

Tetris – это классическая аркадная игра, созданная на языке Python с использованием библиотеки Pygame.

Игрок управляет падающими фигурами, составляя из них сплошные горизонтальные линии для получения очков.

В данной версии проекта реализованы такие элементы интерфейса и логики как: главное меню, экран помощи, система предпросмотра следующей фигуры, а также сохранение лучшего результата.

Проект представляет собой полностью функциональную версию игры с широким пользовательским интерфейсом и продуманной игровой логикой.

### 3. Четкие цели проекта.

• Создать работающую версию игры «Тетрис» с понятным управлением.

• Реализовать основные игровые механики: появление фигур, их падение, вращение, перемещение и удаление (при заполнении линии).

• Реализовать систему состояний приложения (меню, игра, справка).

• Добавить систему предпросмотра следующей фигуры.

• Реализовать систему подсчета очков и сохранения лучшего результата.

• Обеспечить корректную обработку столкновений с границами поля и другими фигурами.

• Обеспечить стабильную работу игры с заданной частотой кадров.

• Продемонстрировать подход к разработке игровых приложений с пользовательским интерфейсом.

### 4. Компоненты проекта.

• Проект состоит из одного исполняемого файла, который включает в себя все компоненты:

• tetris.py – основной скрипт, содержащий весь код игры, включая игровую логику, интерфейс и систему управления состояниями.

### 5. Инструкция по использованию.

**5.1. Запуск:**

• Убедитесь, что установлена библиотека Pygame (pip install pygame). 

• Запустите скрипт с помощью Python (например, с помощью PyCharm).

**5.2. Цель игры:**

• Заполняйте горизонтальные линии падающими фигурами, чтобы зарабатывать очки.

• Игра завершается, если новая фигура не может появиться на поле (достигнута верхняя граница), после чего происходит возврат в меню. Лучший результат сохраняется.

**5.3. Управление:**

• **Стрелка ВЛЕВО (←):** переместить активную фигуру влево.

• **Стрелка ВПРАВО (→):** переместить активную фигуру вправо.

• **Стрелка ВНИЗ (↓):** ускорить падение активной фигуры.

• **Стрелка ВВЕРХ (↑):** повернуть активную фигуру на 90 градусов по часовой стрелке.

• **ESC:** выход в главное меню.

• **Мышь:** управление кнопками в меню и экране помощи.

**5.4. Интерфейс:**

• Главное меню с кнопками Play и Help и лучшим счетом Best.

• Экран помощи с описанием управления.

• Игровое поле размером 11x21 клетка.

• Верхняя панель, отображающая:

* текущий счет (Score)
* лучший результат (Best)
* следующую фигуру (Next)

• Черные клетки с серыми элементами – пустое пространство.

• Цветные клетки – установленные или падающие фигуры.

• За заполнение линии начисляется 10 очков.

## Часть 2. Технический документ.

### 1. Цели разработки.

• Основной целью разработки было создание расширенной модели классической игры Tetris для закрепления навыков программирования на Python и работы с библиотекой Pygame.

• Дополнительно проект направлен на изучение построения пользовательского интерфейса, управления состояниями приложения и работы с файловой системой (сохранение данных).

• Задачи включали работу с матрицами (игровым полем), обработку пользовательского ввода, реализацию системы столкновений, временных интервалов и базовой архитектуры игрового цикла.

### 2. Использованные технологии.

• **Язык программирования:** Python

• **Графическая библиотека:** Pygame

• **Стандартные библиотеки:** random (для генерации фигур), copy (для копирования объектов фигур), json работа с файлами (сохранение рекорда).

### 3. Архитектура проекта.

• Проект реализован как монолитное приложение с элементами конечного автомата состояний.

• Основной цикл: «while game:».

• Логика разделена по состояниям: menu – главное меню, game – игровой процесс, help – экран помощи.

• В каждом кадре выполняются: обработка событий, обновление состояния, проверка игровой логики, отрисовка.

### 4. Структура проекта.

• Инициализация: настройка Pygame, создание окна, шрифтов, кнопок и параметров игры.

• Глобальные переменные: grid, det, det_choice, next_det_choice, color, score, best_score, state и другие. 

• Игровой цикл: основной цикл, в котором происходит управление состояниями и логика игры.

• Функции:

- **draw_menu()** – отрисовка меню.

- **draw_help()** – экран помощи.

- **draw_panel()** – верхняя панель.

- **draw_cell()** – отрисовка контура клетки.

- **CanMove()** – проверка перемещения.

-  **get_next_figure()** – генерация фигур.

- **reset_game()** – сброс игры.

- **save_best_score(), load_best_score()** – работа с рекордом.

• Массивы:

- **grid** – игровое поле.

- **details** – шаблоны фигур.

- **det** – преобразованные фигуры.

### 5. Ключевые компоненты системы.

• **Игровое поле (grid):** Трехмерный список, где каждый элемент содержит: статус ячейки (0 - свободна, 1 - занята), объект Rect, цвет.

• **Фигуры:** представлены в виде координат, преобразуются в объекты pygame.Rect, выбираются случайным образом.

• **Система следующей фигуры:** реализована через next_det_choice и next_color, отображается на панели.

• **Система коллизий:** проверка границ, проверка занятых клеток.

• **Система вращения:** вращение вокруг центральной точки (с координатами (0;0), используется система сдвигов (аналог wall kick).

### 6. Реализация пользовательского интерфейса.

• Интерфейс полностью реализован средствами Pygame.

• Основные элементы: окно приложения, кнопки меню, игровое поле, верхняя панель, текстовые элементы.

• Отрисовка выполняется каждый кадр с помощью функций pygame.draw и pygame.font.

### 7. Процесс разработки.

• Разработка велась поэтапно:

- создание базового игрового окна.
 реализация сетки.

- добавление фигур и их движения.

- реализация столкновений.

- добавление вращения.

- реализация удаления линий.

- добавление меню и интерфейса.

- добавление системы следующей фигуры.

- реализация сохранения рекорда.

### 8. Основные сложности и способы их решения.

• **(1)** Сложность: корректное вращение фигур рядом со стенами и блоками.

Решение: реализована система сдвигов при вращении и функция для проверки возможности сдвига.

• **(2)** Сложность: корректное удаление линий и сохранение цвета.

Решение: копирование как статуса, так и цвета ячеек.

• **(3)** Сложность: управление состояниями приложения.

Решение: введена переменная state и логика переключения.

• **(4)** Сложность: мгновенное застывание фигуры после касания дна поля или другой фигуры.

• Решение: после касания начинается отсчёт таймера, в течение которого можно двигать и вратарь фигуру, но при условии возможности. 

### 9. Текущие ограничения проекта.

• Отсутствие уровней сложности.

• Нет полноценного экрана Game Over.

• Код остается монолитным (без разделения на модули).

• Нет звуковых эффектов.

### 10. Возможные улучшения и планы развития.

• Рефакторинг кода (разделение на модули и классы).

• Добавление уровней сложности и увеличения скорости.

• Добавление звуковых эффектов.

• Реализация экрана Game Over.

• Добавление дополнительных механик (например большее количество очков за несколько одновременно заполненных линий).
